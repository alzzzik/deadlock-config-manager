# Roadmap

Written 2026-10-20, after v0.2.0. Based on research into the Deadlock config ecosystem and into Windows
distribution practice. Effort: **S** about a day, **M** a few days, **L** a week or more.

## Where the app stands

**Competition.** Deadlock Mod Manager (DMM, ~500 stars, millions of downloads) is adding a "perf config"
module in its 2.0 nightlies. It applies community gameinfo presets (OptimizationLock, OptiLock, GameBanana) as
an overlay, re-applies them after updates, and has share codes. Basic "apply a preset" will become a commodity.
Other tools in the space:

| Tool | Scope | Notes |
| --- | --- | --- |
| Grimoire | Mods, autoexec, crosshair | No FPS configs |
| DeadTune | Convar catalog, ranked-safe mode | Alpha, very small |
| Sqooky's updater script | Updates OptimizationLock | Single repo |
| DL-FOV-Fixer | Re-applies FOV after updates | Single setting |

DMM has also had repeated reports of wiping gameinfo configs after game updates (its issues #538, #875). The
OptimizationLock FAQ tells users to avoid it.

**Positioning.** Be the small, trustworthy, focused tool:
- Exact fidelity to the pack author's GitHub source.
- A preview of every change, backups and a real "restore original".
- Never breaking matchmaking.
- Plays nicely next to DMM and Grimoire.

Compete on trust and transparency, not on feature count.

**Valve's moving target.**
- **Since 2026-03-27 (build 6417):** matchmaking refuses to queue if `gameinfo.gi` has *unsupported changes* in
  `Engine2`, `MaterialSystem2`, `NetworkSystem`, `Particles`, `RenderSystem`, `SceneSystem` or
  `WorldRenderer` (`Citadel_StartMatchmaking_UnverifiedPGI`, verified in GameTracking-Deadlock commit
  `8febc71f`). `ConVars` edits are allowed.
  - Checked against Valve's stock file: **alz Stable changes none of those sections**.
  - **OptiLock Recommended changes 16 entries** in them (e.g. `NetworkSystem` fake lag/loss,
    `RenderSystem` pool sizes). It may block ranked queueing.
- **Since 2026-09-24 (build 6698, "Solomon"):** about 77 convars are marked `gameinfo_cannot_override`
  (shadows, fog, outlines, glow). The game silently ignores them when set in `gameinfo.gi`.
- **No reports of bans** for config edits. Valve's stated reason for the lighting lock is artistic intent.

## Now: v0.3, "safe to play"

The most valuable work, because it addresses what actually hurts players today.

1. **Ranked-safety check (M).**
   - Ship a snapshot of Valve's stock values for the guarded sections, refreshed from GameTracking-Deadlock.
   - In the preview and on each pack row, flag packs that change those sections with "May block ranked
     matchmaking".
   - Offer **"Apply ranked-safe"**, which keeps the pack's other changes and puts the guarded sections back to
     stock.
   - Show the same check in the status strip for whatever is currently installed.
2. **Ignored-convar badges (M).**
   - In the preview, mark settings the game now ignores (`gameinfo_cannot_override`) as "Ignored by the game
     since <build>".
   - Players and pack authors can then see which tweaks still do anything.
   - Ship the list as data that updates with the app or the pack index.
3. **Diagnostics (S).**
   - A rotating local log in `%APPDATA%\DeadlockConfigManager\logs` and a panic hook.
   - A **Copy diagnostics** button: version, Windows build, resolved paths with the username redacted, last
     log lines.
   - A GitHub issue form that asks for it. No telemetry.
4. **Mod-manager coexistence (S).** A README section on using the app with DMM and Grimoire. A self-check that
   tells the user when another tool replaced the applied file, with one-click re-apply (partly exists).

## Next: v0.4, "easy to get and keep updated"

5. **Auto-update (S–M).**
   - Tauri updater plugin with signed `latest.json` generated by `tauri-action` on each release.
   - Notify, then install with one click.
   - **Back up the updater private key offline**: losing it strands every install on its current version.
   - Keep publishing releases rather than leaving drafts, since the updater reads `releases/latest`.
6. **Code signing (M).** This removes the "Windows protected your PC" wall that stops many people.
   - **Azure Artifact Signing**, about $10/month: only for individuals in the **US or Canada**. Plugs into
     Tauri's `signCommand`.
   - **SignPath Foundation**: free for MIT open source. Needs a code-signing policy section and a privacy note
     in the README, CI-built releases, MFA, and manual approval per release. The certificate is issued to
     "SignPath Foundation".
   - Pick by where you live. Skip EV certificates: they no longer give instant SmartScreen trust.
7. **winget and Scoop (S each).**
   - **winget:** submit the first version by hand (`wingetcreate new`, `nullsoft`, `Scope: user`), then automate
     with `vedantmgoyal9/winget-releaser` on each published release. It needs a classic PAT.
   - **Scoop:** run your own bucket repo with `autoupdate`.
   - Skip Chocolatey: every version is human-moderated.
8. **GitHub limits, properly (M).**
   - Anonymous API calls are capped at 60 per hour, and "unchanged" (304) replies **still count** unless the
     request is authenticated.
   - Fetch pack files through **jsDelivr** pinned to the commit SHA from the Atom feed, which is cached
     effectively forever.
   - Add an **optional** "Sign in with GitHub" (OAuth device flow, client ID only, token in Windows Credential
     Manager) for people who link many repos.
9. **Automated tests for the UI and installer (M).**
   - Playwright/Vitest against the UI with Tauri's `mockIPC`.
   - A GitHub Actions job that silently installs (`/S`), launches, checks the uninstall entry and uninstalls on
     `windows-latest`.
   - Windows Sandbox isn't available on Windows Home; use a VM or the CI job for clean-machine runs.

## Later: v0.5+, "tuned to your PC"

10. **Auto re-apply after game updates (M).** Watch `gameinfo.gi` and the Steam app manifest build ID. An
    optional tray mode re-applies the chosen pack (ranked-safe) after an update. This is the community's number
    one complaint, and single-purpose tools exist just for it.
11. **Personal overrides on top of a pack (M).** FOV, common FAQ fixes (e.g. "invisible Doorman ult", dark
    portraits) as toggles. Import and export Sqooky's `overrides.gi` format. Overrides survive switching or
    updating packs.
12. **Overlay mode instead of whole-file replace (L).** Apply only the pack's differences on top of Valve's
    current stock file, so a game update that adds new settings doesn't get rolled back. This needs a stock
    baseline per build (same data as item 1).
13. **autoexec.cfg and launch options (S–M).** Apply a pack's `autoexec.cfg` lines; some ignored convars still
    work there. A curated launch-options helper writes Steam's `localconfig.vdf` safely, with Steam closed.
14. **More pack sources (M).** OptimizationLock's subfolders and extra files, GameBanana configs pinned by hash,
    and the `packs.json` format promoted to pack authors (with ranked-safe and target-build fields).
15. **Share codes or profile export (S).** Export the chosen pack plus overrides as a short code or file;
    consider reading DMM's `dmm-perf:` codes.

16. **Saved configs: a local library (M).** Configs that don't live in any repo.
    - **Save current**: store the `gameinfo.gi` and `video.txt` that are currently installed (without the
      hardware lines) as a named config inside the app, with optional notes.
    - Import from a file, folder or zip. Export as a zip or a share code.
    - Saved configs show up as a "My configs" group and get the same preview, apply, pin and restore as repo
      configs.
    - Stored in `%APPDATA%\DeadlockConfigManager\library\<id>\`.
17. **Config store (L).** One place in the app to browse configs: the popular repos plus configs people
    publish from their saved library.
    - **Start without a backend:** a public GitHub repo (e.g. `deadlock-config-index`) holding an
      `index.json` of curated repos and published configs. People add entries by pull request. The app reads it
      through jsDelivr, so there's no server to run and no rate-limit problem.
    - **Publishing from the app:** sign in with GitHub (device flow, already planned in item 8), then the app
      opens a pull request or creates a gist with the saved config.
    - **Later, if it grows:** a real backend for ratings, download counts, reports and moderation.
    - **Things to get right:**
      - Only accept `gameinfo.gi`/`video.txt` text, validated, with a deny list (e.g. `sv_cheats`).
      - Flag configs that would block ranked matchmaking (item 1).
      - Respect authors' licences; some configs don't allow redistribution, so link to them instead.
      - Add a privacy note once anything is uploaded.

## Exploratory

- **Built-in benchmark (L).** Play a replay, capture frame times with PresentMon, and compare packs on the
  user's own PC. Nobody offers this, and players want per-PC proof (community benchmarks show up to ~12%
  differences between popular configs).
- **Linux / Steam Deck AppImage (M).** Both files live outside the Proton prefix (game folder plus
  `~/.local/share/Steam/userdata/...`; Flatpak Steam under `~/.var/app/com.valvesoftware.Steam/...`).
  `tauri-action` can build an AppImage; UAC logic doesn't apply. Watch for Steam Cloud syncing back an old
  `video.txt`.

## Corrections to earlier assumptions

- The ETag cache reduces downloads but doesn't save rate limit for anonymous requests (see item 8).
- Windows Sandbox needs Windows Pro or Enterprise, so it isn't available on the dev PC (Home).
